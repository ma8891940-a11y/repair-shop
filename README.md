# جوالك / Gawalak — إدارة محلات صيانة الموبايل

تطبيق مثبّت (PWA) عربي من اليمين لليسار، ومعاه إنجليزي. بيفتح على تسجيل الدخول، وبعده لوحة التحكم.

---

## التشغيل في 5 دقايق (ويندوز)

### 0) مرة واحدة على الجهاز
ثبّت البرنامجين دول (بالإعدادات الافتراضية):
- **Node.js 22 LTS**: https://nodejs.org
- **Git**: https://git-scm.com/download/win

### 1) نزّل الكود (PowerShell)
افتح **PowerShell** (من قائمة ابدأ اكتب PowerShell) والصق:
```bash
git clone https://github.com/ma8891940-a11y/repair-shop.git
```
```bash
cd repair-shop
```
```bash
npm install
```
> لو الكود عندك من قبل: ادخل الفولدر واكتب `git checkout main` وبعدها `git pull`. **الفرع الوحيد للشغل هو `main`.**

### 2) اعمل مشروع Supabase جديد وجهّز قاعدة البيانات
1. ادخل https://supabase.com/dashboard ← **New project** (أي اسم، واحفظ كلمة سر قاعدة البيانات عندك).
2. استنى المشروع يجهز (دقيقة أو اتنين).
3. من الشريط الجانبي: **SQL Editor** ← **New query**.
4. شغّل أجزاء الإعداد من فولدر `supabase\upgrade` **بالترتيب**، كل جزء في **New query** لوحده: `upgrade_part_1.sql` ثم `upgrade_part_2.sql` ثم اللي بعده لحد آخر جزء.
   - افتح الجزء (بالـ Notepad، أو على GitHub ← **Copy raw file**)، انسخ كل اللي فيه، والصقه، ودوس **Run**.
   - في آخر كل جزء هيظهر سطر فيه `status`: "الجزء 1 خلص. اللي بعده: upgrade_part_2.sql"، وفي آخر جزء: "خلص: المشروع على آخر نسخة".
   - (الملف الواحد `setup_all.sql` بقى أكبر من حد SQL Editor، فبقى لـ psql بس.)
   - لو ظهرت رسايل فيها `skipping` أو `already exists` أو `does not exist, skipping`، دي طبيعية ومش أخطاء.
   - **اتأكد إن النسخة اليومية التلقائية اتجدولت:** من الشريط الجانبي **Integrations ← Cron**، لازم تلاقي `warsha-daily-backup`.
     - لو مش موجودة: من نفس الصفحة فعّل **Cron** (pg_cron).
     - وبعدين في **SQL Editor** شغّل محتوى `supabase\enable_daily_backup.sql`.
5. (للتجربة على طول) اعمل **New query** تاني، والصق محتوى `supabase\seed_demo.sql`، ودوس **Run**.
6. **Authentication ← URL Configuration**:
   - في **Site URL** اكتب `http://localhost:5173`، ودوس **Save**.
   - في **Redirect URLs** دوس **Add URL**، واكتب `http://localhost:5173/**`.
   - ده العنوان اللي رابط تأكيد الإيميل بيرجّعك عليه. لو نزّلت البرنامج على عنوان تاني بعدين، ضيفه هنا كمان.

> **إيميل التأكيد:** البرنامج شغال مع الحالتين من غير ما تغيّر حاجة:
> - **الإيميل الافتراضي بتاع Supabase:** فيه رابط. اضغط عليه من الموبايل أو الكمبيوتر، والتسجيل بيكمّل لوحده.
>   - لو ضغطت عليه من جهاز تاني، ارجع للبرنامج ودوس **"أكدت من الرابط، كمّل"**.
> - **القالب المتعدّل:** فيه كود من 6 أرقام وزرار. اكتب الكود أو اضغط الزرار.
>
> تعديل القالب محتاج SMTP خاص، وخطواته تحت في **"إيميل خاص بيك (SMTP مجاني)"**.

### 3) اكتب مفاتيح المشروع (بنفسك)
محتاج حاجتين من مشروعك:
- **رابط المشروع (Project URL):** شكله `https://xxxx.supabase.co`. هتلاقيه لما تدوس زرار **Connect** اللي فوق في لوحة Supabase.
- **المفتاح العام:** من **Project Settings ← API Keys**. واحد من الاتنين، والاتنين شغالين:
  - **Publishable key**: بيبدأ بـ `sb_publishable_`. لو مش ظاهر، دوس **Create new API Keys**.
  - أو **anon public**: من تبويب **Legacy API Keys**، وبيبدأ بـ `eyJ`. (Supabase بيقول إن المفاتيح القديمة دي هتتلغي آخر 2026، فالأحسن الـ Publishable.)
- **ممنوع** تاخد أي مفتاح اسمه **secret** أو **service_role**.

في PowerShell:
```bash
copy .env.example .env.local
```
```bash
notepad .env.local
```
اكتب القيمتين بعد علامة `=` واحفظ:
```
VITE_SUPABASE_URL=https://xxxx.supabase.co
VITE_SUPABASE_ANON_KEY=sb_publishable_...
```
(اسم الخانة `VITE_SUPABASE_ANON_KEY` بيفضل زي ما هو حتى لو حطيت فيه الـ Publishable key.)
> **ممنوع** تكتب مفتاح `service_role` هنا أو في أي مكان في التطبيق.

### 4) شغّل
```bash
npm run dev
```
افتح http://localhost:5173 في Chrome أو Edge.

**حسابات التجربة** (لو شغّلت `seed_demo.sql`)، وكلمة السر لكلهم `Gawalak#2026`. لو كنت شغّلته قبل تغيير الاسم، الحسابات القديمة `@warsha.demo` بكلمة السر `Warsha#2026` بتفضل زي ما هي:
| الإيميل | الدور |
|---|---|
| `owner@gawalak.demo` | صاحب المحل (كل حاجة، ومعاها "الوضع المالي") |
| `reception@gawalak.demo` | الاستقبال (مسؤولة عن كاش الدرج) |
| `tech@gawalak.demo` | الفني (من غير أسعار ولا بيانات عملاء) |

### 4ب) جرّب النسخة النهائية (أسرع بكتير من npm run dev)
`npm run dev` للتطوير: بيجمّع الكود وانت شغال، فأول فتح والحركة بيبقوا أبطأ من الحقيقي. عشان تشوف البرنامج زي ما هيشتغل عند المستخدم:
1. لو `npm run dev` شغال، اقفله الأول: **Ctrl+C** في نافذة PowerShell.
2. جهّز النسخة النهائية (مرة واحدة بعد أي تحديث للكود، وبتاخد دقيقة تقريبًا):
```bash
npm run build
```
3. شغّلها:
```bash
npm run preview
```
4. افتح http://localhost:5173 (نفس العنوان، فرابط تأكيد الإيميل شغال عادي).
5. **لو الحركة أو الخلفية مش شغالة:** افتح **الإعدادات ← المظهر**. هتلاقي حالة الحركة والسبب والحل:
   - "تقليل الحركة" شغال في الويندوز.
   - أو اتثبتت تلقائيًا عشان البطء.
   - أو تسريع الرسومات مقفول في المتصفح.

> في النسخة النهائية بس البرنامج بيشتغل كتطبيق مثبّت كامل، وبيفتح من غير نت. في `npm run dev` الحاجتين دول مش متاحين.

### 5) ثبّته كتطبيق
شغّل النسخة النهائية الأول (الخطوة 4ب)، وبعدين في Chrome أو Edge: أيقونة التثبيت في آخر شريط العنوان ← **Install**. بيفتح في نافذة لوحده زي أي برنامج.

> زرار التثبيت مش بيظهر في `npm run dev`، بيظهر في النسخة النهائية بس.

## رفع البرنامج مجانًا (عشان روابط التتبع تفتح عند العميل)
وانت شغال على جهازك، البرنامج بيبقى على `localhost`: ده بيفتح عندك بس. عشان العميل يفتح رابط التتبع (من واتساب أو الـ QR)، لازم البرنامج يبقى على رابط عام بيبدأ بـ `https`.
الطريقة دي مجانية ومن غير كارت: **Cloudflare Pages**.

1. **ارفع المشروع على GitHub** (لو مش مرفوع). المستودع ممكن يبقى خاص (Private).
2. افتح https://dash.cloudflare.com واعمل حساب مجاني.
3. من القايمة: **Workers & Pages** ← **Create** ← تبويب **Pages** ← **Connect to Git**، واختار مستودع المشروع.
   - لو أسماء القوايم اتغيّرت عندك، دوّر على "Pages" و"Connect to Git".
4. **إعدادات البناء:**
   - Framework preset: **Vite** (أو None).
   - Build command: `npm run build`
   - Build output directory: `dist`
5. **المتغيرات (Environment variables):** ضيف الاتنين دول بنفس القيم اللي في `.env.local` عندك:
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_ANON_KEY`
   - **ممنوع تحط مفتاح `service_role` هنا خالص.** الواجهة بتستخدم الـ anon key بس.
6. دوس **Save and Deploy**، واستنى دقيقتين. هيديك رابط زي `https://اسم-المشروع.pages.dev`.
7. **في Supabase:** مشروعك ← **Authentication** ← **URL Configuration**:
   - **Site URL:** حط الرابط الجديد.
   - **Redirect URLs:** ضيف نفس الرابط.
8. **في البرنامج:** افتح الرابط الجديد وادخل، وبعدين **الإعدادات ← هوية المحل ← رابط البرنامج العام**، والصق الرابط ودوس حفظ.
   - من دلوقتي كل روابط التتبع في رسايل واتساب والـ QR على الإيصال والاستيكر بتتعمل منه.
   - لو نسيت الخطوة دي والبرنامج مفتوح من `localhost`، الإعدادات ورسالة واتساب بيظهر فيهم تنبيه.

**أي تعديل جديد:** بيترفع لوحده كل ما تعمل push على GitHub.
**بديل مجاني تاني:** Netlify (نفس الإعدادات: `npm run build` و`dist` ونفس المتغيرين).

## تنبيه مهم قبل الاستخدام الحقيقي: رجّع "Confirm email"
لو قفلت **Confirm email** عشان تجرّب بسرعة، **لازم ترجّعه قبل ما تستخدم البرنامج مع موظفين أو محل حقيقي**:
1. **Authentication ← Sign In / Providers ← Email**.
2. شغّل **Confirm email**، ودوس **Save**.

**ليه:** وهو مقفول، Supabase بيعتبر أي إيميل متأكَّد لوحده.
- يعني أي حد يقدر يسجّل بإيميل مش بتاعه.
- **الأخطر:** أي حد يعرف الإيميل اللي بعتّله دعوة موظف يقدر يسجّل بيه ويدخل محلك ويشوف الأجهزة، من غير ما يكون صاحب الإيميل.

**بعد ما ترجّعه:** كل حساب جديد لازم يتأكد (برابط أو بكود). الحسابات اللي اتعملت وهو مقفول بتفضل شغالة عادي.

## إيميل خاص بيك (SMTP مجاني)
**ليه تعمله:**
- خدمة الإيميل الافتراضية في Supabase للتجربة بس. عدد رسايلها في الساعة قليل جدًا، وممكن ما توصلش غير لإيميلات فريق المشروع.
- مش هتقدر تعدّل قالب الإيميل غير لما يبقى عندك SMTP خاص.

اختار خدمة واحدة من الاتنين. **Brevo أسهل لو معندكش دومين (موقع باسمك).**

### الطريقة 1: Brevo (مجاني لحد 300 إيميل في اليوم، ومن غير دومين)
1. ادخل https://www.brevo.com واعمل حساب مجاني، وأكّد إيميلك.
2. **إيميل الإرسال:** من القائمة اللي فوق على اليمين (اسم حسابك) ← **Senders, Domains & Dedicated IPs** ← **Senders** ← **Add a sender**.
   - اكتب اسم المحل، وإيميل بتاعك (مثلًا Gmail).
   - Brevo هيبعتلك رسالة تأكيد، فاضغط على الرابط اللي فيها.
3. **بيانات الـ SMTP:** من نفس القائمة ← **SMTP & API** ← تبويب **SMTP**. هتلاقي:
   - **SMTP Server**: `smtp-relay.brevo.com`
   - **Port**: `587`
   - **Login**: إيميل شكله `xxxx@smtp-brevo.com`. انسخه.
   - دوس **Generate a new SMTP key**، وسمّيه "supabase"، وانسخ المفتاح، واحتفظ بيه عندك. **ده كلمة السر، وما بيظهرش تاني.**
4. كمّل من **"اربطه بـ Supabase"** تحت.

### الطريقة 2: Resend (مجاني لحد 100 إيميل في اليوم، ومحتاج دومين)
1. ادخل https://resend.com واعمل حساب مجاني.
2. **Domains ← Add Domain**: اكتب الدومين بتاعك، واعمل الإعدادات اللي Resend بيطلبها عند الشركة اللي اشتريت منها الدومين، واستنى لحد ما يبقى **Verified**.
   - من غير دومين، Resend مش هيبعت غير لإيميلك انت بس، فاستخدم Brevo.
3. **API Keys ← Create API Key**: سمّيه "supabase"، وانسخ المفتاح. **ده كلمة السر.**
4. البيانات:
   - **Host**: `smtp.resend.com`
   - **Port**: `465`
   - **Username**: `resend`
   - **Password**: المفتاح اللي نسخته.
   - **إيميل الإرسال**: أي إيميل على الدومين بتاعك (مثلًا `no-reply@دومينك.com`).

### اربطه بـ Supabase
1. في مشروعك على Supabase: **Authentication ← Emails ← SMTP Settings** (في نسخ قديمة: **Project Settings ← Authentication**).
2. شغّل **Enable Custom SMTP**، واكتب:
   - **Sender email**: إيميل الإرسال اللي أكدته (في Brevo: إيميل الـ Sender، مش إيميل `smtp-brevo.com`).
   - **Sender name**: اسم المحل أو "جوالك".
   - **Host** و**Port** و**Username** و**Password**: من الخدمة اللي اخترتها.
3. دوس **Save**.
4. **Authentication ← Rate Limits**: خلّي **Rate limit for sending emails** على 30 في الساعة أو أكتر، ودوس **Save**.

### عدّل القالب (بعد ما SMTP يشتغل)
1. **Authentication ← Emails ← Templates ← Confirm signup**.
2. امسح القالب القديم، والصق محتوى `supabase\templates\confirm.html`، ودوس **Save**.
   - القالب ده فيه كود من 6 أرقام وزرار تأكيد، والبرنامج بيقبل الاتنين.

### جرّب
1. سجّل محل جديد بإيميل حقيقي بتاعك، واتأكد إن الرسالة وصلت فيها الكود والزرار.
2. **لو ما وصلتش:**
   - بُص في **Spam**.
   - راجع إن إيميل الإرسال متأكَّد في Brevo أو الدومين Verified في Resend.
   - راجع إن كلمة السر هي مفتاح الـ SMTP، مش كلمة سر حسابك.
   - **في Brevo:** لو مفعّل **Authorized IPs** (من القائمة ← **Security** ← **Authorised IPs**)، Brevo بيرفض الإرسال من سيرفرات Supabase. اقفل الخاصية دي (Deactivate blocking).

**البرنامج بيقولك السبب لو الكود ما اتبعتش:**
| الرسالة في البرنامج | معناها | تعمل إيه |
|---|---|---|
| "الإيميل ما اتبعتش: إعدادات الإرسال (SMTP) فيها مشكلة" | Supabase حاول يبعت وفشل | راجع خطوات "اربطه بـ Supabase" فوق، وAuthorized IPs في Brevo |
| "اتبعتت إيميلات كتير الساعة دي" | حد الإرسال خلص (من غير SMTP خاص حوالي 2 في الساعة) | فعّل Brevo، وارفع Rate limit (الخطوة 4 فوق) |
| "استنى N ثانية وبعدين جرّب تاني" | طلبت الكود تاني بسرعة | زرار "إعادة الإرسال" بيرجع لوحده بعد العداد |

> **ممنوع** تحط مفتاح الـ SMTP في `.env.local` أو في كود البرنامج. مكانه في إعدادات Supabase بس.

## النقل لمشروع Supabase جديد
1. اعمل مشروع جديد وكرّر الخطوة 2 (أجزاء `supabase/upgrade` بالترتيب، وإعداد الـ URL). الـ `seed_demo.sql` اختياري، والـ SMTP والقالب لو عايزهم.
2. غيّر القيمتين في `.env.local` للمشروع الجديد، واقفل `npm run dev` (Ctrl+C) وشغّله تاني.
3. البيانات القديمة ما بتتنقلش لوحدها: خد نسخة احتياطية قبل النقل، واسترجعها في المشروع الجديد بالخطوات اللي في قسم "استرجاع نسخة احتياطية" تحت.

## استرجاع نسخة احتياطية
الاسترجاع بيرجّع كل بيانات المحل من ملف النسخة (`.gawalak`): العملاء، والأجهزة بأرقام طلباتها، والفلوس والقيود، والمخزون، والموردين، والإعدادات.
**بيشتغل على محل جديد فاضي بس**، في نفس مشروع Supabase أو في مشروع جديد. ممنوع على محل فيه شغل، عشان ما يحصلش خلط.

**قبل ما تبدأ، محتاج:**
- ملف النسخة (`.gawalak`) وكلمة السر بتاعته.
  - لو المحل القديم لسه شغال: الإعدادات ← النسخ الاحتياطي ← "صدّر النسخة".
  - أو نزّل واحدة من "النسخ اليومية على السيرفر".

**الخطوات:**
1. **سجّل محل جديد** بإيميل صاحب المحل (من شاشة الدخول ← "سجّل محل جديد"). كمّل المعالج للآخر عادي، والبيانات اللي هتكتبها فيه هتتبدل بتاعة النسخة.
   - لو هتسترجع في نفس المشروع والإيميل القديم لسه مستخدم في المحل القديم، سجّل بإيميل تاني.
2. افتح **الإعدادات ← النسخ الاحتياطي**، وروح لقسم **"فتح نسخة للتأكد منها"**.
3. اكتب **كلمة سر النسخة**، ودوس **"اختار ملف"** واختار ملف `.gawalak`.
4. هيظهر "النسخة سليمة" ومعاه عدد الصفوف. تحتها دوس **"استرجع النسخة"**، وبعدين **"أيوه، استرجع"**.
5. استنى لحد ما يظهر "البيانات رجعت". البرنامج هيفتح من الأول لوحده.

**اتأكد بنفسك:**
- **الوضع المالي:** لازم يظهر "الدفتر متوازن"، وأرقام الخزن مطابقة للمحل القديم.
- **الأجهزة:** نفس أرقام الطلبات، ونفس الحالات، ونفس اللي على العملاء.

**بعد الاسترجاع:**
- **الموظفين:** بيرجعوا في السجل بأساميهم كـ"موظفين سابقين" (عشان تعرف مين عمل إيه زمان). بس محدش فيهم يقدر يدخل. ابعتلهم دعوة من جديد من شاشة الموظفين.
- **الصور:** صور الأجهزة ما بترجعش، لأنها مش جوه ملف النسخة (النسخة فيها البيانات بس). لوجو المحل للإيصال والفاتورة بيرجع.
- **أقفال الأجهزة:** كلمات سر وأنماط أجهزة العملاء ما بترجعش، لأنها أصلًا مش بتطلع في النسخة عشان الأمان.
- **ملصقات الـ QR القديمة:**
  - في مشروع جديد: بتفضل شغالة.
  - في نفس المشروع (والمحل القديم لسه موجود): الأجهزة بتاخد أكواد تتبع جديدة، فاطبع ملصق جديد لو محتاج.

**لو ظهرت رسالة:**
- "المحل ده فيه شغل": المحل مش فاضي. سجّل محل جديد واسترجع فيه.
- "كلمة السر غلط أو الملف اتعدّل": اتأكد من كلمة السر.
- "أرقام النسخة مش مطابقة" أو "فيه قيد مش متوازن": الملف اتعدّل أو باظ. **مفيش أي حاجة بتتغيّر** في الحالة دي، لأن الاسترجاع كله بيتلغي.

## تحديث مشروع Supabase شغّال (من غير ما تبدأ من الأول)

**الطريقة السهلة: أجزاء الترقية `supabase/upgrade/upgrade_part_1.sql`، `upgrade_part_2.sql`، ...**
- كل جزء أصغر من حد **SQL Editor** (300KB بالكتير)، فبيشتغل من غير رسالة "Query is too large".
- كل جزء بيشوف لوحده إيه اللي اتشغّل قبل كده في قاعدة البيانات، وبيشغّل الناقص من ملفاته بس.
- **آمن تشغّل أي جزء أكتر من مرة:** اللي اتطبق قبل كده بيتخطى، ومش بيحصل أي ضرر.
- كل ملف جوّه الجزء بيتشغّل لوحده: لو واحد فشل، اللي قبله بيفضل، وتقدر تشغّل نفس الجزء تاني بعد ما تصلّح السبب.
- **بيقف من غير ما يغيّر أي حاجة** في حالتين (ابعت الرسالة للمطوّر):
  - `E_UPGRADE_GAP`: فيه ملف أحدث متشغّل وملف أقدم منه ناقص.
  - `E_UPGRADE_ORDER`: شغّلت جزء قبل اللي قبله. الرسالة بتقولك تشغّل أنهي جزء الأول.

الخطوات:
1. **قبلها (احتياطي):** من البرنامج: الإعدادات ← النسخ الاحتياطي ← صدّر نسخة واحفظها عندك.
2. شغّل **كل الأجزاء بالترتيب**، كل جزء في **New query** لوحده: `upgrade_part_1.sql` ثم `upgrade_part_2.sql` ثم اللي بعده لحد آخر جزء.
   - افتح الجزء على GitHub (فولدر `supabase/upgrade`) ← زرار **Copy raw file** ← Supabase ← **SQL Editor** ← **New query** ← الصق ← **Run**.
   - الأجزاء اللي اتطبقت عندك قبل كده بتخلص في ثانية من غير ما تعمل حاجة، فمش لازم تعرف إنت واقف فين.
   - لو SQL Editor سألك عن "destructive operation" (عشان فيه `drop` و`revoke` جوه الملفات): دوس **Run** عادي. الأوامر دي جزء من الترقية ومش بتمسح بيانات.
   - **شغّل الأجزاء من آخر نسخة على GitHub دايمًا:** مع التحديثات الجديدة ممكن ملف ينتقل من جزء لجزء أو يتضاف جزء جديد، وده عادي.
3. في آخر كل جزء هيظهر سطر فيه `status`:
   - "الجزء N خلص. اللي بعده: ...": كمّل باللي بعده.
   - "خلص: المشروع على آخر نسخة": كده تمام، و`applied_files` = عدد ملفات `supabase/migrations`.
   - "فيه ملف ما اتطبقش": شوف الرسالة اللي فوق، وابعتها.
4. لو ظهر خطأ: انسخ الرسالة كلها وابعتها. ولو الخطأ في ملف معيّن، اللي قبله اتطبق خلاص.

> **الملف الواحد `supabase/upgrade_existing.sql`** لسه موجود (نفس الترقية كلها مرة واحدة)، بس بقى أكبر من حد SQL Editor، فبقى لـ psql بس.
> الأجزاء بتتعمل أوتوماتيك مع `npm run db:setup-file`، وفيه اختبار بيفشل لو أي جزء عدّى الحد أو ما اتحدّثش.

> الإثبات: `npm run test:upgrade` بيعمل قواعد في كل المراحل (فاضية، وبعد ملف 1، و16، و28، و33، و39، و43، و47، و55، وآخر نسخة)،

**الطريقة اليدوية:**

### المساعد الذكي (اختياري ومجاني)
المساعد بيستخدم **Gemini API المجاني** من Google. ممنوع أي خدمة مدفوعة.
- **من غير مفتاح:** المساعد بيبان مقفول برسالة واضحة، و"دليل الأعطال المدمج" شغال عادي (مجاني ومن غير نت).
- **اللي بيتبعت لـ Google:** حسب المكان، ومن غير اسم العميل ولا رقمه ولا عنوانه أبدًا. أي رقم أو إيميل أو اسم عميل ظاهر على الشاشة بيتشال قبل ما الطلب يخرج:
  - التشخيص: الموديل ووصف العطل.
  - الاستلام: الموديل والعطل، وأعطال نفس الموديل في المحل ومتوسط تكلفتها.
  - الشراء: أسماء الأصناف وكمياتها.
  - المالية: أرقام مجمّعة بس (الكاش، والإيراد، والمصروف، والربح...). مقفولة افتراضيًا.
  - واتساب: الغرض والحالة. الرسالة بتتكتب بمتغيرات ({name}، {order}...) والبرنامج بيملاها على جهازك.
  - التقارير: الأرقام، وأسماء الفنيين بتتشفّر (فني 1، فني 2).
  - الزرار العايم: اسم الشاشة وسؤالك.
- **الاقتراح ما بيتنفذش لوحده:** بيظهر، وانت تدوس "تطبيق" لو عايزه.
- **الإعدادات ← المساعد:** تشغيل وقفل لكل مكان، ومين من الموظفين يستخدمه، وحد يومي للمحل. وده بيتطبق في قاعدة البيانات نفسها.
- **من غير نت أو من غير مفتاح:** رسالة هادية بتقول السبب، واقتراحات تاريخ المحل والدليل المدمج وشرح كل شاشة شغالين.
- **المفتاح بيتحط على السيرفر بس (أسرار Supabase)، مش في `.env.local` ولا في كود الواجهة.**

**1) خد المفتاح المجاني:**
1. افتح https://aistudio.google.com وادخل بحساب Gmail.
2. دوس **Get API key**، وبعدين **Create API key**.
3. انسخ المفتاح (بيبدأ غالبًا بـ `AIza`). مش محتاج كارت ولا دفع.
4. ما تبعتوش لحد، وما تحطوش في أي ملف في المشروع.

**الطريقة السهلة (للمبتدئ): سكريبت بيعمل الخطوات 2 و3 لوحده:**
1. افتح Terminal جوه فولدر المشروع (في ويندوز: افتح الفولدر، واكتب `cmd` في شريط العنوان فوق، ودوس Enter).
2. اكتب الأمر ده ودوس Enter:
```bash
npm run setup:assistant
```
3. هيسألك عن **كود المشروع**: انسخ رابط مشروعك من Supabase والصقه، أو الكلمة اللي قبل `.supabase.co`.
4. هيفتح المتصفح لتسجيل الدخول في Supabase: ادخل ووافق، وارجع للـ Terminal.
5. هينشر المساعد. لو سألك "متأكد؟" اكتب `y` ودوس Enter.
6. هيسألك عن **مفتاح Gemini**: الصقه ودوس Enter. المفتاح مش هيظهر وانت بتكتبه (ده طبيعي)، ومش بيتحفظ في أي ملف في المشروع.
7. لما يقول "خلاص"، افتح البرنامج ← **الإعدادات ← المساعد**، ولازم تلاقي "المساعد شغال على السيرفر".

لو حاجة فشلت، السكريبت بيقول السبب بالعربي. وتقدر تعمل نفس الخطوات بإيدك تحت.

**2) انشر المساعد على مشروع Supabase (مرة واحدة):** افتح Terminal جوه فولدر المشروع، واكتب الأوامر دي واحد واحد.
- سجّل دخول (هيفتح المتصفح، ووافق):
```bash
npx supabase login
```
- انشر الدالة. غيّر `PROJECT_REF` بكود مشروعك: هو الكلمة اللي في أول رابط المشروع، يعني في `https://abcd1234.supabase.co` الكود هو `abcd1234`.
```bash
npx supabase functions deploy assistant --use-api --remote=PROJECT_REF
```
  - هيسألك "متأكد؟" اكتب `y` ودوس Enter.
  - لو قالّك إن `--remote` مش معروف (نسخة قديمة من الأداة)، استخدم `--project-ref=PROJECT_REF` بداله.

**3) حط المفتاح في أسرار Supabase:**
- من الـ Terminal (غيّر `المفتاح` بالمفتاح اللي نسخته):
```bash
npx supabase secrets set GEMINI_API_KEY=المفتاح --remote=PROJECT_REF
```
- أو من موقع Supabase: افتح مشروعك ← **Edge Functions** ← **Secrets**، وضيف سر جديد اسمه `GEMINI_API_KEY` وقيمته المفتاح. (لو أسماء القوايم اتغيّرت عندك، دوّر على "Secrets" جوه Edge Functions.)

**4) جرّب:** افتح **المساعد الذكي** من القايمة الجانبية (أو من صفحة أي جهاز تحت). لازم رسالة "المساعد محتاج مفتاح" تختفي، ويظهر زرار "اقترح الأسباب وخطوات الفحص".

**مكان المساعد:** في القايمة الجانبية "المساعد الذكي" (لصاحب المحل والفني)، وكمان في صفحة كل جهاز. لو مش شغال ما بيختفيش، وبيقول السبب بالظبط:
- "المساعد محتاج مفتاح": الدالة منشورة ومفيش `GEMINI_API_KEY` (الخطوة 3).
- "المساعد مش منشور على السيرفر": الدالة مش منشورة (الخطوة 2).
- "من غير نت".

وفي كل الحالات "دليل الأعطال المدمج" شغال.

**إعدادات اختيارية (في نفس مكان الأسرار):**
- `AI_PROVIDER`: الخدمة المستخدمة. الافتراضي `gemini`، ودلوقتي هي الوحيدة. لو حبيت تضيف خدمة مجانية تانية بعدين، بتتضاف في `supabase/functions/_shared/ai.ts` وتغيّر الإعداد ده بس.
- `GEMINI_MODEL`: اسم موديل Gemini لو عايز تغيّره. من غيره البرنامج بيستخدم `gemini-flash-latest`، ولو Google شالته بيجرّب `gemini-3-flash` وبعده `gemini-2.5-flash` لوحده.
- لو الحد المجاني بتاع Google خلص في يوم، المساعد بيقول إنه مش متاح دلوقتي، والدليل المدمج بيظهر.

## الخلفية المتحركة (لو وقفت)
- **السبب:** الإعدادات ← المظهر بتعرض سبب وقوفها، وخطوات الحل لويندوز 10 و11، وزرار "رجّع الحركة".
  - "الويندوز طالب تقليل الحركة": الحركة بترجع لوحدها أول ما تغيّرها، من غير ما تحدّث الصفحة.
  - "اتثبتت عشان البطء".
- **توفير الطاقة:** لو الجهاز لابتوب على "توفير الطاقة" (Energy saver في Chrome)، أو الشاشة بتنزل لـ 30 أو 48 هرتز، الإطارات بتبقى أقل من 50، بس الجهاز مش بطيء. البرنامج بيفرّق بين ده وبين البطء الحقيقي، وما بيثبّتش الخلفية بالغلط.
- **شاشة التشخيص:** دوس **Ctrl+Alt+Shift+M** في أي وقت، أو زرار "تشخيص الحركة" في الإعدادات ← المظهر. (الاختصار القديم Ctrl+Shift+D كان محجوز في Chrome وEdge.) بتظهر شاشة صغيرة فيها:
  - عدد الإطارات دلوقتي.
  - الخلفية شغالة ولا واقفة، وليه.
  - حالة حارس الأداء.
  - ودوس نفس الزراير تاني عشان تقفلها.

- قاعدة الاختبار المحلية بتتنضف لوحدها قبل أي تشغيل، وكل اختبار بيمسح الداتا اللي عملها. ده بيشتغل بس على قاعدة على نفس الجهاز (127.0.0.1)، وأي قاعدة تانية ما بيلمسهاش. ولو عايز تبص على الداتا بعد الاختبار: `TEST_DB_RESET=0` أو `E2E_DB_RESET=0`.
- `npm run test:e2e`: محتاج Supabase محلي (Docker). بيشتغل على `npm run dev`.
- `E2E_PROD=1 npm run test:e2e`: نفس الاختبارات على نسخة الإنتاج (build + preview)، وده الأقرب للاستخدام الحقيقي.
- بعد أي migration جديدة: `npm run db:setup-file` عشان يتحدّث `setup_all.sql` و`upgrade_existing.sql` وأجزاء `supabase/upgrade` (فيه اختبار بيفشل لو نسيت).

## التصدير (Excel وPDF)
- في أي قايمة أو تقرير أو كشف حساب: زرار **"تصدير"** ← Excel، أو PDF / طباعة، أو CSV.
- الملف فيه نفس اللي ظاهر على الشاشة بالظبط: نفس الفلتر والبحث والفترة والترتيب.
- **Excel:**
  - الشيت من اليمين للشمال.
  - فوقه اسم المحل والفترة وتاريخ الطباعة.
  - المبالغ أرقام تقدر تجمعها، وتحت سطر إجمالي.
- **PDF:** بتفتح صفحة A4 بلوجو المحل. من نافذة الطباعة اختار "حفظ كـ PDF" (Save as PDF).

## الطباعة
- **"طباعة وإرسال":** بعد حفظ الاستلام بيظهر في نفس الشاشة (وكمان في صفحة الجهاز).
  - طباعة حرارية، وطباعة ورقية A4، واستيكر الجهاز، وملصق QR للتتبع، وإرسال واتساب للعميل.
  - كل زرار بضغطة واحدة من غير ما تسيب الشاشة، وجنبه "اتطبع" أو "اتبعت".
- **الإعدادات ← الطباعة:**
  - تختار أنهي حاجة تتعمل تلقائي بعد الاستلام.
  - مقاس الاستيكر: 30×20، أو 38×25، أو 40×30 (الافتراضي)، أو 50×25، أو 50×30، أو 58×40، أو 60×40، أو اكتب العرض والارتفاع بإيدك.
  - الإطار، والإزاحة لو الطباعة طالعة مزحزحة، وعدد النسخ، و"طباعة اختبار".
- **في نافذة الطباعة للاستيكر:** اختار الطابعة الحرارية، وخلي حجم الورق نفس مقاس الاستيكر، والهوامش None.
- **"رقم محفوظ":** بيفضل محفوظ على الجهاز، وتقدر تنسخه أو تطبعه على الاستيكر.
- **الطابعة:** بتتختار من نافذة الطباعة، والمتصفح بيفتكر آخر طابعة. اختار الحرارية للاستيكر والإيصال الحراري، والعادية للـ A4.
- الإيصال والملصق: طابعة حرارية 80مم. في نافذة الطباعة اختار الطابعة، وخلّي الهوامش "بلا".
- الفاتورة وكشوف الحساب وتقرير اليوم: A4. ولو عايز PDF اختار "حفظ كـ PDF".

## الفروع
- **المحل اللي ليه فرع واحد:** مفيش أي حاجة اتغيرت. كل البيانات القديمة اتنقلت لـ"الفرع الرئيسي"، وأرقام الطلبات زي ما هي (2026-0042).
- **فرع جديد:** الإعدادات ← الفروع ← "فرع جديد". اكتب الاسم وبادئة لأرقام الطلبات (حروف إنجليزي أو أرقام، زي B2).
  - أرقام طلبات الفرع هتبقى B2-2026-0001، وعدّها لوحده.
  - الفرع بيتعمله خزنة لكل طريقة دفع في المحل.
- **مبدّل الفروع (فوق):** بيظهر لما يبقى فيه أكتر من فرع.
  - اختار فرع: الاستلام والعمليات بتتسجل عليه، والقوايم والتقارير بتاعته بس.
  - "كل الفروع" (لصاحب المحل): القوايم والتقارير بتجمّع كل الفروع، وفي الوضع المالي "مقارنة بين الفروع".
- **الخزن:** الدفعة والبيع بيتسجلوا على خزنة من نفس الفرع. وتحويل الفلوس بين خزن الفروع من "تحويل بين الخزن".
- **المخزون:** كل فرع ليه مخزونه بالمتوسط المرجّح بتاعه. "تحويل لفرع" من نافذة الصنف في المخزون (الكمية بتخرج بتكلفتها وتدخل الفرع التاني بنفس القيمة).
- **جهاز لفرع تاني:** من صفحة الجهاز ← "ابعت لفرع". الجهاز بيبان "في الطريق" لحد ما الفرع التاني يدوس "استلم الجهاز في الفرع".
- **الموظفين:** الفريق ← "الفروع" جنب كل موظف (أو وقت الدعوة). الموظف بيشوف ويشتغل في فروعه بس، حتى من قاعدة البيانات نفسها. صاحب المحل بيشوف كل الفروع.
- **الشركاء:** شريك على المحل كله أو على فرع. شريك الفرع نصيبه من ربح الفرع ده بس.
- **من غير نت:** كل عملية بتفتكر فرعها، وبتتسجل فيه لما النت يرجع حتى لو بدّلت الفرع.
- **قفل فرع:** من الإعدادات ← الفروع. بشرط ما يكونش فيه أجهزة مفتوحة ولا فلوس في خزنه ولا مخزون. بياناته وقيوده بتفضل في الدفتر.

## قوائم الملء السريع
- الماركة والموديل ونوع الجهاز واللون والتصنيف والقطعة وغيرهم: اكتب في الخانة واختار من القايمة، أو "إضافة «...» للقائمة" لو مش موجود.
- جنب كل بند في القايمة "×" لإزالته منها (بتأكيد). الأجهزة والأصناف القديمة اللي عليها القيمة دي ما بتتغيرش.
- القايمة واحدة للمحل كله: اللي بتضيفه من الاستلام بيظهر في المخزون والجرد ولكل الموظفين.
- الإعدادات ← القوائم: كل القوايم في مكان واحد، و"مين يقدر يضيف ويشيل" (صاحب المحل دايمًا).
- من غير نت: الإضافة والحذف بيتسجلوا على الجهاز وبيتبعتوا لما النت يرجع.

## جدول الجرد
- "عدد السطور" جنب "إضافة سطور": اكتب العدد اللي عايزه (1 افتراضيًا).
- Enter في آخر سطر بيزوّد سطر واحد. وفيه حذف لكل سطر، وتحديد كذا سطر وحذفهم، و"حذف السطور الفاضية".
- اللصق من Excel بيملا الجدول بعدد السطور اللي نسختها بس.

## الأدوار والصلاحيات
- الإعدادات ← الأدوار والصلاحيات: فيه 5 أدوار جاهزة (مدير فرع، واستقبال، وفني، وكاشير مبيعات، ومحاسب)، وتقدر تعدّلها أو تعمل دور جديد باسم من عندك.
- كل دور ليه جدول: الأقسام (الأجهزة، والاستلام، والعملاء، والمخزون، والمبيعات...) قصاد يشوف، ويضيف، ويعدّل، ويحذف، ويشوف المبالغ والأرباح، ويطبع ويصدّر.
- الفريق ← "الأدوار" جنب كل موظف: دور أو أكتر، واستثناءات ليه هو بس (دوسة على الخانة: زي الدور ← مسموح ← ممنوع).
- اللي ملوش صلاحية على حاجة ما بيشوفهاش خالص: لا في القايمة ولا في البحث ولا لوحة التحكم، والحماية في قاعدة البيانات نفسها.
- صاحب المحل عنده كل الصلاحيات دايمًا. والتغيير بيتطبق على طول.
- المرحلة دي بتشيل صلاحيات بس. فتح حاجات جديدة للموظف (زي الوضع المالي والأرباح) جاي في المرحلة الجاية.
- نوع الفرع (الإعدادات ← الفروع): صيانة بس، أو مبيعات بس، أو الاتنين. الأقسام اللي مالهاش علاقة بتختفي، وتغيير النوع ما بيمسحش أي بيانات.


## اختيار الصنف والبيع من غير رصيد
- خانة الصنف (البيع، والشراء، والمرتجعات، والهالك، وقطع الجهاز) بتكتب فيها: جزء من الاسم أو النوع أو الماركة أو الموديل أو الجودة أو الباركود، بالعربي أو الإنجليزي. الأسهم وEnter للاختيار، وقارئ الباركود بيختار على طول.
- لو الصنف مش موجود: "إضافة صنف جديد «...»" من نفس النافذة (النوع، والماركة، والموديل، والجودة، واللون، والتكلفة، وسعر البيع، والكمية)، والاسم بيتكوّن لوحده.
- الإعدادات ← المخزون ← "السماح بالبيع بدون رصيد" (مقفول افتراضيًا):
  - مقفول: لو الكمية مش كفاية، سجّل الكمية والتكلفة من نافذة البيع نفسها وكمّل.
  - مفتوح: البيع بيكمّل والصنف بيتعلّم "محتاج تسوية" بالأحمر. أول ما تسجّل الكمية والتكلفة (شراء أو رصيد)، الحسابات بتتسوى لوحدها بقيد متوازن.
- المخزون والتقرير فيهم فلاتر بالنوع والماركة والموديل والجودة.

## الطابعات ومصمم الطباعة
- الإعدادات ← الطابعات ومصمم الطباعة: أضف طابعاتك من الموديلات الجاهزة (Xprinter 58 و80مم، وRongta، وEpson TM-T20، وطابعات الملصقات، وHP وCanon A4 وA5، وEpson LX-310 النقطية)، وعدّل العرض والطول والهامش لو محتاج.
- المتصفح ما بيقدرش يعرض الطابعات المتوصلة بالجهاز: الملف بيحدد مقاس الورقة، ونافذة الطباعة بتفتح على المقاس ده. اختار الطابعة الصح في النافذة أول مرة والمتصفح بيفتكرها.
- مصمم الطباعة: لإيصال الاستلام (حراري وA4) وفاتورة التسليم: أظهر أو أخفي أي خانة، ورتّبها بالسحب أو بالأسهم، وغيّر حجم الخط والمحاذاة والعريض، وزوّد نص حر. المعاينة على آخر جهاز بالمقاس الحقيقي، و"طباعة اختبار"، و"رجّع الافتراضي". القالب ممكن يكون للمحل كله أو لفرع معيّن.
- الأرقام على الورق (الإجمالي والمدفوع والباقي...) دايمًا من البرنامج نفسه؛ القالب بيتحكم في الشكل بس.

### الطباعة المباشرة (اختياري، لسه ما اتفعّلتش)
- البرنامج المساعد المجاني المقترح: **QZ Tray** (مفتوح المصدر). بعد تثبيته على الكمبيوتر، البرنامج يقدر يعرض الطابعات المتوصلة ويطبع على طول من غير نافذة الطباعة.
- النسخة المجانية بتطلب "سماح" أول مرة لكل جهاز (فيه خانة "افتكر اختياري").
- ربطه محتاج إضافة مكتبة `qz-tray` للبرنامج، ومستنيين موافقة صاحب المشروع قبل تثبيتها (قاعدة المكتبات الجديدة).

## صور الاستلام من موبايل الفني
- في نافذة "اتسجّل الجهاز" وفي صفحة الجهاز: زرار **صور من الموبايل** بيعرض QR.
- الفني يمسحه بكاميرا موبايله، فتتفتح صفحة رفع من غير تسجيل دخول، ويصوّر. الصور بتظهر على الجهاز في المحل على طول.
- الرابط صالح 30 دقيقة لجهاز واحد بس، ومن غير أي بيانات للعميل، والحد 6 صور زي ما هو.
- العميل بيشوف صور الاستلام في صفحة التتبع (برابط التتبع بس)، وصفحة الجهاز فيها "سجل الجهاز بالـ IMEI".

## قوايم الفحص والتوقيع
- **الإعدادات ← قوايم الفحص:** قالب لكل ماركة (عام، Apple، Samsung، Xiaomi، Oppo، Realme). تضيف بند جاهز أو بند باسمك، وترتّب، وتشيل، و"رجّع الجاهز".
- الجهاز بياخد قالب ماركته لوحده. و**اطبع ورقة الفحص** من صفحة الجهاز: A4 باسم المحل، ومكان التوقيع.
- نافذة "تأكيد التسليم" فيها توقيع العميل (اختياري)، وبيتطبع على الفاتورة وورقة الفحص.

## الأمان: كلمة السر الرئيسية والتحقق بخطوتين
- **الإعدادات ← الأمان ← كلمة السر الرئيسية (اختيارية):** لو حددتها، القيد العكسي وتعديل الفلوس والحذف والخصم الكبير محتاجين الكلمة (حتى منك). محدش يقدر يقراها، و5 محاولات غلط بتقفل ربع ساعة.
  - لو نسيتها: مفيش طريقة ترجعها من البرنامج (ده مقصود). الحل من Supabase ← SQL Editor: `update public.shop_secrets set master_hash = null;` (بيشيلها لكل المحلات في المشروع ده، فاستخدمه لو المشروع ليك لوحدك).
- **التحقق بخطوتين (2FA):** "فعّل التحقق بخطوتين" وامسح الكود بتطبيق Google Authenticator أو Microsoft Authenticator. بعد كده الدخول بيطلب كود من التطبيق.
  - مجاني ومدمج في Supabase. لو الزرار طلع خطأ: Supabase ← Authentication ← Multi-Factor ← اتأكد إن **TOTP** متفعّل (Enabled).
  - قاعدة البيانات نفسها ما بتفتحش بيانات المحل لحساب عليه 2FA إلا بعد الكود.

## الأجهزة المستعملة
- **المبيعات والمخزون ← الأجهزة المستعملة:** "شراء جهاز مستعمل" (الماركة، والموديل، والـ IMEI، والسعر، وبيانات البائع، وصورة البطاقة)، و"بيع"، والربح لكل جهاز.
- بيانات البائع لصاحب المحل بس (زرار "البائع")، ورقم البطاقة مشفّر، وكل فتح بيتسجل في سجل النشاط.
- محتاج ملف `0048_used.sql` (بيعمل مكان خاص في Storage اسمه `seller-ids` لوحده).

## عمولات الفنيين
- **الإعدادات ← الفنيين ← قواعد العمولة:** نسبة من المصنعية أو مبلغ ثابت، لكل الفنيين أو فني معيّن، ولكل الأعطال أو نوع عطل.
- العمولة بتتسجل لوحدها وقت التسليم. **التقارير ← عمولات الفنيين:** العمولة والمكافآت والجزاءات والرصيد، وتصدير Excel وPDF، وكشف حساب كل فني.

## بيانات تجريبية
- في آخر خطوة في التسجيل اختار "جرّب ببيانات تجريبية"، أو من **الإعدادات ← النسخ الاحتياطي**. لما تخلص: "امسح بيانات التجربة" (كل قيد بيتعكس، والأرصدة بترجع صفر).

## الكتالوج وبوابة الجملة
- **الإعدادات ← الكتالوج:** افتح الكتالوج، واختار الأصناف، وشارك الرابط على واتساب أو فيسبوك.
- **ملف العميل ← بوابة عميل الجملة:** رابط خاص للعميل يشوف فيه كشف حسابه ويبعت طلبية.

## إشعارات تيليجرام (اختياري ومجاني)
- **الإعدادات ← التنبيهات ← إشعارات تيليجرام:** الخطوات مكتوبة جوه الشاشة (@BotFather ثم @userinfobot).
- محتاجة إضافة **pg_net** في Supabase: Database ← Extensions ← pg_net ← Enable (ملف `0054_telegram.sql` بيحاول يفعّلها لوحده).

## التصنيفات والخدمات
- **المبيعات والمخزون ← التصنيفات:** تصفح بالبلاطات (رئيسي ← فرعي ← الأصناف)، وزرار "بيع" على كل صنف.
- أول مرة: "ابدأ بالتصنيفات الجاهزة"، وبعدين ضيف وعدّل ورتّب بنفسك.
- **الخدمة:** في فورم الصنف اختار النوع "خدمة" (زي التنظيف أو السوفت وير): بتتباع من غير مخزون.

## إشعارات على الجهاز (Web Push) (اختياري ومجاني)
نفس إشعارات الجرس (أقساط متأخرة أو قربت، وأجهزة جاهزة من 10 أيام، وأصناف قربت تخلص)، بتوصل على الكمبيوتر أو الموبايل **حتى والبرنامج مقفول**.
- **مجانية:** بتستخدم خدمة الإشعارات اللي جوه المتصفح نفسه (Chrome وEdge وFirefox وSafari). مفيش أي خدمة مدفوعة ولا SMS.
- **كل واحد بيوصله اللي في صلاحيته بس:** الفني ما يوصلوش أقساط ولا فلوس. وكل إشعار بيوصل مرة واحدة، وما بيوصلش لو اتقرا في البرنامج.
- **الوقت:** الإعدادات ← التنبيهات ← "وقت الإشعارات" (الافتراضي من 9 الصبح لـ 9 بالليل بتوقيت القاهرة). برّه الوقت ده الإشعارات بتستنى.
- **زرارين في الإشعار:** "افتح" (بيفتح البرنامج على الحاجة نفسها) و"اتقرا".
- **عند الخروج من البرنامج:** الإشعارات بتتقفل على الجهاز ده لوحدها، عشان اللي يدخل بعدك ما يوصلوش إشعاراتك.

**التجهيز (مرة واحدة، صاحب المشروع):**
1. على جهازك، جوه فولدر المشروع:
```bash
npm run push:keys
```
   هيطلع 3 سطور: `VAPID_PUBLIC_KEY` و`VAPID_PRIVATE_KEY` و`PUSH_CRON_SECRET`. **دول أسرار:** ما تبعتهمش لحد، وما تحطهمش في `.env.local` ولا في أي ملف.
2. في Supabase: **Edge Functions ← Secrets ← Add new secret**، وضيف الـ 3 دول، ومعاهم `VAPID_SUBJECT` وقيمته `mailto:` وبعدها إيميلك (مثلًا `mailto:me@gmail.com`).
3. انشر الدالة (اكتب كود مشروعك مكان `<كود المشروع>`):
```bash
npx supabase functions deploy push --no-verify-jwt --project-ref <كود المشروع>
```
