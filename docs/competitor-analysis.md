# تحليل منافسين: MobiCareX و QuickSale

> تاريخ التحليل: 16 نوفمبر 2026
> الطريقة: تصفح عبر Chrome + قراءة HTML العام لكل صفحة + فحص روابط داخلية، سرعة، تجاوب، أمان أساسي.
> ملاحظة: الملف ده أفكار وتحليل بس — مفيش أي نصوص أو كود أو صور أو براند منقولة.

## 0. ملاحظة مهمة قبل أي حاجة

الموقعين **مش متاجر بيع منتجات للمستهلك**، الاتنين **برامج إدارة (B2B SaaS / Software)** لأصحاب المحلات:

| | MobiCareX | QuickSale |
|---|---|---|
| النوع | منصة سحابية (ويب) لإدارة **محلات ومراكز صيانة الموبايل** | مجموعة برامج **حسابات ومخازن عامة** (برنامج ويندوز + تطبيقات موبايل) |
| العميل المستهدف | ورش صيانة، محلات موبايل جديد/مستعمل، إكسسوارات، سلاسل فروع | تجزئة/جملة/توزيع لأي نشاط تقريباً |
| "الشراء" | تسجيل حساب + تجربة 3 أيام (سلف-سيرفس) | نموذج طلب/واتساب/تليفون + تحميل من Google Play (بيع بمساعدة مندوب) |

يعني "تدفق الشراء" هنا = **من زيارة الموقع → التجربة/التواصل → الاشتراك**. لو تطبيقك متجر للمستهلك، الجزء التاني (لوحة إدارة المحل) هو اللي هتستفيد منه أكتر.

## 1. MobiCareX — https://mobicarex.com/

### 1.1 الصفحات اللي اتصفحت
| الصفحة | الحالة | ملاحظة |
|---|---|---|
| `/` الرئيسية | ✅ تعمل | Landing page واحدة طويلة (~3000px) |
| `/registration` | ✅ تعمل | معالج تسجيل من **8 خطوات** |
| `/login` | ✅ تعمل | دخول بإيميل/باسورد + **دخول بـ QR** + نسيت كلمة المرور |
| `sitemap.xml` | ✅ | فيه صفحتين بس (الرئيسية والتسجيل) |
| روابط خارجية | فيسبوك المطوّر فقط | مفيش واتساب، مفيش تليفون، مفيش يوتيوب |

**الموقع عبارة عن صفحة تسويقية واحدة + بوابة تسجيل/دخول.** مفيش صفحات أسعار، مفيش FAQ، مفيش مدونة، مفيش صفحة "عن الشركة"، مفيش فيديوهات أو صور للبرنامج من جوه.

### 1.2 المميزات المعلنة (ملخص بأسلوبي)
1. **تذاكر صيانة** كاملة: استلام → تشخيص → تعيين فني → حالات (انتظار/جاري/مكتمل/تم التسليم).
2. **توثيق صور الجهاز بالـ QR**: الفني يمسح كود ويرفع صور الجهاز من موبايله وقت الاستلام (يحمي من خلافات الخدوش).
3. **لينك فاتورة للعميل عبر واتساب** — العميل يتابع الحالة والسعر والعربون من غير حساب.
4. **مرتجعات وضمان** مع تاريخ كامل للتذكرة.
5. **ربط قطع الغيار بالإصلاح** + خصم تلقائي من المخزون + تقرير ربحية القطع.
6. **Checklist فحص للأجهزة (آبل)** قبل الصيانة يتطبع ويوقّع عليه العميل.
7. **نقطة بيع (POS)** على الكمبيوتر والموبايل + باركود + مصمم ملصقات.
8. **بيع وشراء المستعمل** بتتبع السيريال.
9. **مخزون**: فئات، تنبيه نقص، هوالك، استيراد Excel.
10. **خزائن متعددة** + طرق دفع محلية (كاش، بنك، فيزا، محافظ، InstaPay) + إغلاق يومي.
11. **موردين ومشتريات** وكشوف حساب.
12. **الفاتورة الإلكترونية (ETA)** لمصلحة الضرائب المصرية — ربط مباشر.
13. **ملف عميل** بمرفقات ومديونية + استيراد Excel.
14. **عمولات الفنيين** (سلف/مكافآت/جزاءات) + تصدير PDF/Excel.
15. **داشبورد** مباشر.
16. **صلاحيات تفصيلية** + كلمة سر رئيسية للعمليات الحساسة + سجل نشاط + **إشعارات Telegram**.
17. عربي/إنجليزي + Dark mode + **ساب دومين لكل محل** (عزل بيانات).

### 1.3 تدفق المستخدم
```
الرئيسية ── "تجربة مجانية 3 أيام" ──► تسجيل (8 خطوات: شركة + ساب دومين + بيانات دخول + ...)
                                       └─► كود تأكيد على الإيميل ─► دخول على subdomain المحل
         ── "Find Account" ──► دخول (باسورد أو QR)
```
- مفيش أي قناة "اسأل قبل ما تشترك" (لا واتساب، لا شات، لا تليفون).
- مفيش أسعار معلنة → المستخدم مش عارف هيدفع كام بعد الـ 3 أيام.

### 1.4 التصميم وتجربة الموبايل
- **الرئيسية**: ثيم داكن بخلفية متحركة (Canvas نجوم/شبكة)، كروت مميزات بسيطة. شكل "تقني" حديث.
- **صفحة التسجيل**: ثيم فاتح مختلف تماماً (Card بعمودين) — **عدم اتساق بصري** بين الصفحتين.
- خليط لغات: الهيرو إنجليزي، والمحتوى عربي، وصفحة التسجيل إنجليزي → إحساس غير متسق للمستخدم المصري.
- **صفر صور** في الرئيسية (لا لقطات شاشة للبرنامج، لا فيديو) → صعب تتخيل المنتج.
- تجاوب الموبايل: فيه viewport سليم وقواعد CSS لـ 600px و 400px، ومفيش overflow أفقي. الكروت بتتحول عمود واحد.
- الأداء: الصفحة خفيفة (6 ملفات بس، صفر صور) لكن الـ load حوالي **~5 ثواني** عندي (DOMContentLoaded ~3 ثواني) — غالباً بسبب سيرفر/الأنيميشن.
- أمان: HTTPS ✅، منع الـ iframe (X-Frame-Options) ✅، robots.txt بيمنع الصفحات الخاصة ✅، Schema/OG موجودين ✅.

### 1.5 نقاط القوة
- **تخصص عميق في نيتش واحدة** (صيانة الموبايل في مصر) — المميزات مكتوبة من واقع شغل المحل الفعلي.
- مميزات ذكية ومميزة: صور الاستلام بالـ QR، لينك الحالة للعميل على واتساب، checklist الفحص، عمولات الفنيين.
- **ETA e-invoice** + طرق دفع مصرية (InstaPay/محافظ) = ميزة تنافسية قوية محلياً.
- سحابي بالكامل بدون تثبيت، ساب دومين لكل محل، صلاحيات وسجل نشاط.
- تسجيل سلف-سيرفس بدون كارت ائتمان.

### 1.6 نقاط الضعف والمشاكل
| المشكلة | التأثير |
|---|---|
| مفيش صفحة أسعار | تردد واتخاذ قرار أبطأ |
| تجربة **3 أيام فقط** | قصيرة جداً لنظام محتاج إدخال مخزون وتدريب فنيين |
| تسجيل من **8 خطوات** قبل ما يشوف البرنامج | تسرب كبير في الـ funnel |
| الساب دومين **لا يمكن تغييره** | قرار نهائي بدري جداً في رحلة المستخدم |
| صفر لقطات شاشة/فيديو/ديمو | المستخدم بيشتري "مجهول" |
| مفيش واتساب/تليفون/شات | العميل المصري متعود يسأل قبل ما يشترك |
| مفيش آراء عملاء أو أرقام حقيقية، وفيه ادعاء "الأكبر في الشرق الأوسط" بدون دليل | ضعف ثقة |
| الـ checklist لأجهزة آبل بس | سوق أندرويد (الأكبر في مصر) مش مغطى بنفس العمق |
| خليط عربي/إنجليزي + ثيمين مختلفين | إحساس منتج غير مكتمل |
| مفيش تطبيق موبايل native (ويب بس) | مفيش إشعارات push، ولا كاميرا/باركود بنفس سلاسة التطبيق |

## 2. QuickSale — http://www.quicksale-eg.online/

### 2.1 ⚠️ مشكلة تقنية أساسية
- **الموقع مش بيفتح في Chrome الحديث**: الدومين شغال على HTTP بس، و**HTTPS بيفشل في الـ TLS handshake**. Chrome بيحاول يرقّي لـ HTTPS فيظهر صفحة خطأ. اضطريت أقرأ الصفحات عن طريق تحميل الـ HTML العام.
- معنى كده إن **نسبة كبيرة من الزوار بيشوفوا صفحة خطأ أو تحذير "غير آمن"** — ومش هيدخلوا بيانات في نموذج على موقع غير مشفر.
- نموذج التواصل بيبعت البيانات لعنوان `https://` على نفس الدومين اللي الـ HTTPS بتاعه مش شغال → **غالباً النموذج بيفشل** وبيطلع للمستخدم رسالة خطأ (alert).
- الـ OG image والأيقونات بتشاور على دومين تاني (quicksale.site) — توزيع البراند على دومينين.

### 2.2 الصفحات اللي اتصفحت (18 رابط داخلي)
| الصفحة | الحالة |
|---|---|
| الرئيسية | ✅ 200 |
| تفاصيل البرنامج المكتبي | ✅ 200 (صفحة ثقيلة ~120KB) |
| تفاصيل تطبيق الموبايل للمالك | ✅ 200 |
| تفاصيل تطبيق المناديب | ✅ 200 |
| تفاصيل تطبيق العملاء (Market) | ✅ 200 |
| سياسة الخصوصية | ✅ 200 |
| عن الشركة، المدونة، الوظائف، اتصل بنا، حلول مخصصة، FAQ، الشركاء، آراء العملاء، شروط الاستخدام، صفحات التحميل (×4) | ❌ **404** |
| sitemap.xml | ❌ 404 |

**14 من 18 رابط داخلي مكسورين (~78%)** — منهم "شروط الاستخدام" اللي بتبقى مطلوبة قانونياً. وفيه رابط placeholder بيشاور على دومين وهمي (`yourdomain.com`).

### 2.3 المنتجات والمميزات (ملخص)
منظومة من 4 منتجات:
1. **برنامج ويندوز (Desktop)**: مخزون، حسابات، فواتير، مشتريات، **أقساط**، بنوك وشيكات، صلاحيات، نسخ احتياطي محلي/سحابي، شبكة متعددة المستخدمين، شاشة بيع تاتش، 5 طرق تسعير، 23 نموذج طباعة، فيديوهات تعليمية داخلية. بيستهدف قائمة طويلة جداً من الأنشطة.
2. **تطبيق مناديب** (إضافة سنوية): خطوط سير وخرائط، فواتير وتحصيلات من الموبايل، **يعمل أوفلاين** + مزامنة بزرار، صلاحيات لكل مندوب.
3. **تطبيق موبايل مستقل للمالك**: محاسبة ومخزون كاملة من الموبايل، تجربة مجانية، **إنشاء متجر ويب في دقائق** من جوه التطبيق.
4. **تطبيق مجاني لعملاء التاجر (B2B portal)**: العميل يشوف كشف حسابه وفواتيره ودفعاته، يتصفح المنتجات، ويبعت طلبية.

إضافات: جدول مقارنة بين المنتجين، FAQ، آراء عملاء، فيديوهات يوتيوب، زر واتساب عائم، تقسيط حتى 6 شهور، ضمان استرجاع 30 يوم.

### 2.4 تدفق المستخدم
```
الرئيسية ──► كروت المنتجات ──► "اطلب عرض سعر" ──► نموذج (اسم/إيميل/تليفون/منتج/نشاط) ──► (غالباً يفشل)
         ──► "حمّل التطبيق" ──► Google Play
         ──► زر واتساب / تليفون
         ──► "تفاصيل إضافية" ──► صفحات المنتج (4 شغالة / 4 مكسورة)
```
- البيع معتمد على **التواصل البشري** (واتساب/تليفون) أكتر من السلف-سيرفس.
- مفيش تسجيل أو ديمو أونلاين للبرنامج المكتبي.

### 2.5 التصميم وتجربة الموبايل
- RTL عربي سليم، خط عربي واضح، أيقونات، أنيميشن ظهور عند السكرول (AOS).
- breakpoints لـ 1024 / 768 / 480 → التصميم متجاوب نظرياً.
- **شريط عدّاد تنازلي** للعرض "ينتهي خلال 3 أيام" — بفحص الكود: **العداد بيتعمل من جديد مع كل زيارة** (دايماً 3 أيام من دلوقتي). ده أسلوب ضغط مزيف، ولو العميل لاحظه الثقة بتضيع.
- استخدام مكثف للإيموجي وكلمات مبالغة ("ثورة"، "سحر"، "مذهل") → شكل إعلاني أكتر منه احترافي.
- صور بدون lazy-loading، صفحات تفاصيل ثقيلة، jQuery + مكتبات خارجية؛ تحميل الصفحة ~3–4 ثواني من السيرفر عندي.

### 2.6 نقاط القوة
- **منظومة متكاملة**: مالك + مناديب + عملاء التاجر — فكرة "التطبيق المجاني لعميل التاجر" (كشف حساب + طلبيات) قوية جداً وبتعمل network effect.
- **أوفلاين + مزامنة** للمناديب — مهم جداً في مصر.
- **نظام أقساط** — احتياج حقيقي للسوق.
- إنشاء متجر أونلاين بسرعة من نفس بيانات المخزون.
- محتوى تعليمي (فيديوهات، لقطات شاشة)، جدول مقارنة، FAQ، آراء عملاء، واتساب عائم، تقسيط وضمان استرجاع.
- خبرة معلنة 13 سنة.

## 4. قائمة المميزات المقترحة لتطبيقك

> افتراض: تطبيقك لمحلات الموبايل/الصيانة والإكسسوارات (الأقرب للاتنين). لو نيتش مختلف، الأفكار بتتنقل بسهولة.

### 4.1 الأساس (MVP) — لازم يكون موجود يوم الإطلاق
1. **تذاكر صيانة** بحالات واضحة + تعيين فني + تاريخ كامل للتذكرة.
2. **توثيق الاستلام بالصور** من موبايل الفني (QR أو داخل التطبيق مباشرة) + توقيع العميل على الشاشة.
3. **Checklist فحص قابلة للتخصيص** لكل الماركات (Samsung, Xiaomi, Oppo, Realme… مش آبل بس) — القالب يتعدل من المحل نفسه.
4. **POS** بباركود (كاميرا الموبايل كقارئ) + طباعة حرارية + ملصقات.
5. **مخزون** بتنبيه نقص، سيريال/IMEI للأجهزة، استيراد Excel.
6. **مستعمل**: شراء/بيع بتتبع IMEI + صورة بطاقة البائع (مع التنبيه على حماية البيانات).
7. **خزائن + طرق دفع مصرية** (كاش، InstaPay، محافظ، فيزا) + إغلاق يومي.
8. **صلاحيات + سجل نشاط**.
9. **عربي أولاً** (RTL سليم) مع إنجليزي، **وواجهة متسقة بلغة واحدة لكل مستخدم**.

### 4.2 الحاجات اللي هتتفوق بيها عليهم
| الفكرة | ليه أحسن |
|---|---|
| **ويب + تطبيق موبايل native + أوفلاين مع مزامنة تلقائية** (مش بزرار) | بيجمع ميزة الاتنين؛ النت في المحلات مش مستقر |
| **صفحة تتبع للعميل** (لينك/QR على الإيصال) فيها حالة الجهاز، صور الاستلام، السعر، العربون، الضمان + زر "موافقة على التكلفة الإضافية" | أقوى من لينك الفاتورة؛ بيقلل المكالمات ويوثّق الموافقة |
| **رسائل واتساب تلقائية** عند تغيير الحالة (استلام/جاهز/تذكير ضمان) عبر WhatsApp Business API | الاتنين بيعتمدوا على الإرسال اليدوي أو Telegram للمالك بس |
| **بوابة عملاء الجملة** (للمحلات اللي بتورّد لمحلات تانية): كشف حساب + طلبيات | فكرة QuickSale بس جوه نفس المنصة، مش تطبيق منفصل |
| **أقساط** للأجهزة بجدولة وتذكير | MobiCareX مش عنده |
| **فاتورة إلكترونية ETA + إيصال إلكتروني (B2C e-receipt)** | ميزة MobiCareX + خطوة زيادة |
| **متجر أونلاين/كتالوج** متولد تلقائياً من المخزون (أجهزة مستعملة + إكسسوارات) بلينك يتشارك على فيسبوك/واتساب | QuickSale عنده بس منفصل عن الصيانة |
| **تحليلات ذكية**: أكتر أعطال متكررة لكل موديل، متوسط وقت الإصلاح لكل فني، القطع اللي بتاكل الربح، توقع نفاد المخزون | تحويل البيانات لقرارات |
| **Multi-branch** بتحويل مخزون بين الفروع وتقارير موحدة | للسلاسل |
| **سجل أعطال لكل IMEI** (لو الجهاز رجع تاني) + تحذير من أجهزة مبلّغ عنها مسروقة (لو فيه مصدر بيانات قانوني) | ثقة في سوق المستعمل |
| **Onboarding سريع**: تسجيل بخطوة واحدة (رقم موبايل + OTP)، **ديمو ببيانات تجريبية جاهزة**، والساب دومين يتختار بعدين ويتعدل | بيقضي على أكبر نقطة تسرب عند MobiCareX |
| **مساعد إعداد**: استيراد مخزون من صورة فاتورة/Excel، قوالب جاهزة لأشهر القطع والأسعار | تقليل وقت البداية |

### 4.3 موقع/صفحة الهبوط — اعمل اللي هما معملوهوش
1. **صفحة أسعار شفافة** (شهري/سنوي، حسب عدد الفروع/المستخدمين) — سعر واحد متسق في كل مكان.
2. **تجربة 14 يوم** + خطة مجانية محدودة (مثلاً 30 تذكرة/شهر) بدل 3 أيام.
3. **ديمو تفاعلي** أو فيديو 60 ثانية + لقطات شاشة حقيقية.
4. **زر واتساب + شات** للأسئلة قبل الاشتراك، ورقم دعم واضح.
5. **آراء عملاء حقيقية** (بأسماء محلات وصور بإذنهم) وأرقام قابلة للتحقق — بدون ادعاءات "الأكبر".
6. **مفيش عدادات مزيفة** ولا خصومات وهمية — العروض بتاريخ انتهاء حقيقي.
7. **HTTPS، صفر روابط مكسورة** (فحص روابط آلي في الـ CI)، sitemap، صفحات خصوصية وشروط فعلية.
8. **ثيم واحد ولغة واحدة متسقة** من الرئيسية لحد التسجيل لحد البرنامج.
9. صفحات حسب الاستخدام: "لمراكز الصيانة"، "لمحلات المستعمل"، "للسلاسل".
10. مركز مساعدة + فيديوهات قصيرة بالعامية المصرية.

### 4.4 جودة تقنية وتجربة موبايل
- Mobile-first فعلاً: أزرار كبيرة، bottom navigation، عمليات أساسية (تذكرة جديدة/بيع/بحث IMEI) بخطوتين.
- PWA أو تطبيق native مع push notifications.
- هدف أداء: الصفحة الرئيسية < 2 ثانية على 4G، Lighthouse > 90.
- نسخ احتياطي تلقائي يومي + تصدير بياناتك في أي وقت (بيبني ثقة وبيقلل الخوف من الـ lock-in).
- 2FA للمالك + كلمة سر للعمليات الحساسة (زي حذف فاتورة/خصم كبير).

## 6. تفاصيل للبناء (مستخلصة من التحليل)

### 6.1 الأدوار والصلاحيات
| الدور | يقدر يعمل |
|---|---|
| المالك (Owner) | كل حاجة + إعدادات + تقارير + صلاحيات + خزائن + حذف/خصم كبير بكلمة سر رئيسية |
| مدير فرع | تشغيل الفرع، تقارير الفرع، تحويل مخزون |
| موظف استقبال/كاشير | فتح تذكرة، صور الاستلام، POS، تحصيل، تسليم |
| فني | التذاكر المعيّنة له، تشخيص، طلب قطع، تغيير الحالة، عمولته |
| عميل نهائي (بدون حساب) | صفحة تتبع بلينك/QR: الحالة، الصور، السعر، الموافقة، الضمان |
| عميل جملة (اختياري، مرحلة 3) | كشف حساب + طلبيات |

### 6.2 دورة حياة تذكرة الصيانة
```
استلام ─► فحص/تشخيص ─► بانتظار موافقة العميل ─► جاري الإصلاح ─► بانتظار قطعة
   │                          │ (رفض)                    │
   │                          ▼                          ▼
   │                     مرفوض/إرجاع بدون إصلاح ◄── تعذّر الإصلاح
   ▼
جاهز للتسليم ─► تم التسليم ─► (خلال الضمان) مرتجع/إعادة إصلاح ─► يرجع لـ "جاري الإصلاح"
```
كل انتقال: يتسجل في تاريخ التذكرة (مين/إمتى/ليه) ويقدر يبعت إشعار واتساب للعميل.

### 6.3 الكيانات الأساسية (Data model مبدئي)
- **Tenant/Company** ← **Branch** ← **User** (role, permissions)
- **Customer** (اسم، موبايل، مرفقات، رصيد/مديونية)
- **Device** (ماركة، موديل، IMEI/سيريال، لون، حالة: جديد/مستعمل)
- **RepairTicket** (عميل، جهاز، عطل، تشخيص، فني، حالة، سعر تقديري/نهائي، عربون، ضمان، tracking token)
  - **TicketPhoto**، **InspectionChecklist** (قالب + نتائج)، **TicketEvent** (history)، **TicketPart** (قطعة + كمية + تكلفة)
- **Product / Part** (فئة، باركود، تكلفة، سعر، حد أدنى) + **StockMovement** (نوع، فرع، كمية، مرجع)
- **Sale / Invoice** + **InvoiceLine** + **Payment** (طريقة الدفع، خزينة)
- **Purchase** + **Supplier** + كشف حساب
- **UsedDeviceDeal** (شراء/بيع مستعمل + مستند البائع)
- **CashBox** (خزينة) + **DailyClosing** + **Transfer**
- **Commission / StaffLedger** (عمولة، سلفة، مكافأة، جزاء)
- **InstallmentPlan** (مرحلة 3)
- **ActivityLog**، **Notification**

### 6.4 الشاشات الأساسية (MVP)
1. تسجيل/دخول (موبايل + OTP) + إعداد المحل بخطوة واحدة + بيانات ديمو
2. الداشبورد (تذاكر اليوم حسب الحالة، مبيعات اليوم، الخزينة، نواقص المخزون)
3. قائمة التذاكر (فلترة بالحالة/الفني/البحث بالـ IMEI أو الموبايل) + تذكرة جديدة + تفاصيل التذكرة
4. شاشة الفني (تذاكري فقط، تغيير حالة سريع)
5. POS (بحث/باركود بالكاميرا، سلة، دفع، طباعة)
6. المخزون (أصناف، حركات، استيراد Excel، نواقص)
7. العملاء والموردين (ملف، كشف حساب)
8. الخزائن والإغلاق اليومي
9. التقارير الأساسية
10. الإعدادات (فروع، مستخدمين، صلاحيات، قوالب طباعة، قوالب فحص، رسائل واتساب)
11. صفحة التتبع العامة للعميل

### 6.5 متطلبات غير وظيفية
- عربي RTL أولاً + إنجليزي، Dark mode، Mobile-first.
- أوفلاين للعمليات الأساسية (تذكرة/بيع) مع مزامنة تلقائية وحل تعارضات.
- عزل بيانات كل محل (multi-tenant)، HTTPS، 2FA للمالك، سجل نشاط، نسخ احتياطي يومي، تصدير البيانات.
- أداء: < 2 ثانية على 4G، طباعة حرارية 58/80mm و A4.
- روابط التتبع العامة: token عشوائي غير قابل للتخمين، ومن غير بيانات شخصية زيادة عن اللازم.

### 6.6 قرارات لسه مفتوحة (محتاجة منك)
- النيتش النهائي: صيانة موبايل بس، ولا صيانة + بيع، ولا عام؟
- التقنية: ويب + PWA، ولا تطبيق native (Flutter/React Native) + لوحة ويب؟
- نموذج التسعير: اشتراك شهري/سنوي، حسب الفروع أو المستخدمين؟ وهل فيه خطة مجانية؟
- مزود واتساب (WhatsApp Business API رسمي) وتكلفته.
- ربط ETA في الـ MVP ولا مرحلة 2؟

## 7. ملحق: قيود التحليل
- ما سجلتش حساب في أي من الموقعين (التسجيل بيطلب بيانات شخصية وقبول شروط)، فالتحليل الداخلي للبرنامج مبني على **المميزات المعلنة** مش على تجربة فعلية من جوه.
- نافذة المتصفح ما اتصغرتش لعرض الموبايل (النافذة كانت maximized)، فتقييم الموبايل مبني على فحص الـ viewport وقواعد الـ CSS المتجاوبة وعدم وجود overflow أفقي، مش على لقطة شاشة بحجم موبايل.
- QuickSale ما فتحش في Chrome خالص (خطأ HTTPS)، فاتقرأ من الـ HTML العام بس.
- أوقات التحميل اتقاسـت من جهاز واحد وشبكة واحدة — للاسترشاد مش أرقام قاطعة.
